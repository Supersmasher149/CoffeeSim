# C++ LSP Support for OpenCode

## Goal

Enable project-local C++ language-server support in OpenCode for EspressoLab's
C++20 sources and headers, using the compile commands generated by the existing
CMake build.

## Scope

- Update `.opencode/opencode.json` only for the implementation.
- Preserve the existing OpenCode schema declaration and Mem0 plugin.
- Register `clangd` as the C++ LSP server.
- Pass `--compile-commands-dir=build` so clangd uses the repository's active
  build database and exact compiler flags.
- Associate common C and C++ source/header extensions with the server.

No C++ source, CMake, dependency, editor, or global OpenCode configuration
changes are required. CMake already enables
`CMAKE_EXPORT_COMPILE_COMMANDS`, and the repository's `build/` directory
contains `compile_commands.json`.

## Configuration

The project config will add an `lsp.clangd` entry shaped as follows:

```json
{
  "command": ["clangd", "--compile-commands-dir=build"],
  "extensions": [
    ".c", ".cc", ".cpp", ".cxx",
    ".h", ".hh", ".hpp", ".hxx"
  ]
}
```

The command intentionally uses the system `clangd` resolved through `PATH`,
matching the existing local toolchain instead of introducing a repository
managed binary.

## Verification

1. Validate the resulting JSON and confirm the config retains its existing
   schema and plugin entries.
2. Confirm `build/compile_commands.json` exists and contains the project
   translation units.
3. Start `clangd` with the configured arguments and verify it remains able to
   initialize against the project database.

OpenCode loads configuration at startup, so users must quit and restart
OpenCode after the config change.
